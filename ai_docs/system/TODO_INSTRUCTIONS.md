# Инструкции по работе с TODO

## Основные принципы

1. **ВСЕГДА перечитывать документацию** из `ai_docs/` перед началом работы
2. **Использовать CLI инструмент** `todo.txt-cli` для управления задачами
3. **Следовать CODESTYLE.md** - НИКОГДА не использовать `Any`, `Optional`, относительные импорты
4. **Обновлять документацию** при любых изменениях

## Настройка CLI

```bash
# Клонируем todo.txt-cli
git clone https://github.com/todotxt/todo.txt-cli.git

# Устанавливаем переменную окружения
export TODO_FILE=todo.txt

# Используем CLI
./todo.txt-cli/todo.sh ls A    # Показать задачи приоритета A
./todo.txt-cli/todo.sh add "Новая задача +tag"  # Добавить задачу
./todo.txt-cli/todo.sh do 1    # Отметить задачу 1 как выполненную
```

## Приоритеты

- **A** - Критично, блокирует работу
- **B** - Важно, нужно сделать
- **C** - Желательно, можно отложить

## Теги

- `+api` - работа с API
- `+bot` - функциональность бота
- `+docs` - документация
- `+testing` - тестирование
- `+refactor` - рефакторинг
- `+critical` - критическая ошибка

## Проекты

- `project:szgmu_integration` - интеграция с СЗГМУ
- `project:bot_v2` - новая версия бота
- `project:quality` - улучшение качества кода

## Контекст

- `@ai` - задача для ИИ
- `@wait_user` - ожидает действий пользователя
- `@from_user` - получено от пользователя

## Примеры команд

```bash
# Показать все задачи приоритета A
./todo.txt-cli/todo.sh ls A

# Показать задачи с тегом +api
./todo.txt-cli/todo.sh ls +api

# Добавить новую задачу
./todo.txt-cli/todo.sh add "(A) Исправить ошибку в API +api +critical"

# Отметить задачу как выполненную
./todo.txt-cli/todo.sh do 1

# Показать статистику
./todo.txt-cli/todo.sh stats
```

## Важно!

- **НИКОГДА** не использовать `Any` или `Optional` в коде
- **ВСЕГДА** использовать встроенные типы Python 3.9+
- **ОБЯЗАТЕЛЬНО** обновлять документацию при изменениях
- **ПРИОРИТЕТ** - работоспособность, а не фичи
